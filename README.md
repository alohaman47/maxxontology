# MAXX — market ontology (minimal app)

แอปหน้าเดียว ไม่มี build step ไม่ต้อง npm install
เปิดจาก GitHub Pages ได้ตรงๆ แก้ทุกอย่างผ่าน GitHub web editor ได้

---

## ขึ้น GitHub Pages (ผ่านเว็บล้วน)

1. สร้าง repo ใหม่ ตั้งเป็น **Public**
2. หน้า repo → **Add file** → **Upload files** → ลากทั้งโฟลเดอร์ลงไป
   (ลากทั้งโฟลเดอร์ได้เลย GitHub เก็บโครงสร้าง `assets/` กับ `src/` ให้)
3. **Commit changes**
4. **Settings** → **Pages** → Source: `Deploy from a branch`
   → Branch: `main` / `/ (root)` → **Save**
5. รอ 1–2 นาที เปิด `https://<user>.github.io/<repo>/`

แก้ไฟล์ทีหลัง: กดไฟล์ → ไอคอนดินสอ → แก้ → Commit
กด `.` บนหน้า repo เพื่อเปิด VS Code บนเว็บเต็มรูปแบบ

## แผนที่ไฟล์

| ไฟล์ | หน้าที่ | ต้องแก้บ่อยไหม |
|---|---|---|
| `src/adapter.js` | **ข้อมูลทั้งหมด** — พอร์ต สินค้า บริษัท งบ กระแสโซเชียล ตำรา | ใช่ ที่เดียว |
| `src/ontology.js` | ชนิดวัตถุ ความสัมพันธ์ ตัวเดินกราฟ สมุดปูม | เมื่อเพิ่มชนิดวัตถุใหม่ |
| `src/compute.js` | อัตราส่วนพื้นฐาน สภาพตลาด หลักฐาน ด่าน ขนาดไม้ | เมื่อเพิ่ม/แก้กติกา |
| `src/ui.js` | สี่หน้า + แผ่นรายละเอียด | เมื่อเพิ่มหน้า |
| `src/main.js` | โหลดข้อมูลเข้าออนโทโลยี + เราเตอร์ | แทบไม่ต้อง |
| `assets/app.css` | ธีม (รองรับโหมดมืดอัตโนมัติ) | ตามใจ |

## ต่อข้อมูลจริง

แก้ `src/adapter.js` ที่เดียว — ไฟล์อื่นอ่านผ่าน `loadData()` เท่านั้น

```js
export async function loadData(){
  const r = await fetch('./data/snapshot.json');
  return r.json();          // คืนรูปร่างเดิม แล้วตั้ง synthetic:false
}
```

แหล่งข้อมูล:

- **ราคา / ATR / ADX** — MT5 เขียนไฟล์ JSON ออกมา แล้ว push ขึ้น repo หรือยิงเข้า gist
- **งบการเงิน** — SEC XBRL companyfacts (ฟรี ไม่ต้องมี key)
  `https://data.sec.gov/api/xbrl/companyfacts/CIK##########.json`
- **กระแสโซเชียล** — StockTwits / Reddit API นับ mention + sentiment ต่อ 24 ชม.
- **สมุดผลย้อนหลัง** — export จาก MT5 หรือ PTJ แล้วแทนที่ตัวปั้นจำลองใน `buildEvidence()`

⚠️ `tv` (มูลค่าต่อ 1 point ต่อ 1 lot) **ต้องดึงจาก `SYMBOL_TRADE_TICK_VALUE` จริงของโบรก**
ถ้าใช้ค่าที่ใส่ไว้ตอนนี้ การคำนวณล็อตจะเพี้ยน

## ตรรกะที่ฝังอยู่ในระบบ

**ด่านก่อนเข้าไม้** — ตั๋วจะปรากฏต่อเมื่อผ่านครบ

| ด่าน | กติกา |
|---|---|
| EVIDENCE | ขอบล่างของช่วงความเชื่อมั่น 90% ต้องพ้นศูนย์ และตัวอย่าง ≥ 30 ไม้ |
| REGIME | ตำราต้องถูกออกแบบมาเพื่อสภาพตลาดปัจจุบันของสินค้านั้น |
| SPREAD / LIQUIDITY | FX: สเปรด ≤ 12% ของ ATR · หุ้น: ไม้ ≤ 1% ของวอลุ่มวัน |
| EARNINGS | ห้ามเข้าภายใน 5 วันก่อนประกาศงบ |
| CROWDING | บล็อกเมื่อกระแสโซเชียลสูงพร้อม P/E ปลายบนกรอบ ธงแดง หรือความเสี่ยงถูกปั่น |
| FUNDAMENTALS | ผ่านเกณฑ์ขั้นต่ำที่ตำรานั้นประกาศไว้เอง |
| COOLDOWN | ห้ามเปิดไม้ใหม่บนสินค้าเดิมภายใน 30 นาทีหลังขาดทุนที่นั่น |
| DAILY CAP | ไม้ใหม่ไม่เกิน 6 ไม้ต่อวัน |
| CLUSTER BUDGET | ไม่เกินงบทั้งกลุ่มตัวเองและกลุ่มแม่ทุกชั้น |
| PORTFOLIO HEAT | ความร้อนรวมไม่เกิน 4R |

**สามอย่างที่ทำให้นี่เป็นออนโทโลยี ไม่ใช่แดชบอร์ด**

1. `Company` (ตัวธุรกิจ) แยกจาก `Instrument` (ตั๋วที่ซื้อขาย) — ROIC เป็นของธุรกิจ ไม่ใช่ของตั๋ว
2. ทุกอัตราส่วนเป็น **ฟังก์ชัน** ไม่ใช่ค่าที่เก็บ — แก้งบไตรมาสเดียว ทุกตัวเลขขยับตาม
3. กลุ่มความเสี่ยงเป็น **ลำดับชั้น** — ถือ NAS100 แล้วซื้อหุ้นเทคเพิ่ม คือเดิมพันเดิม ไม่ใช่การกระจาย

## ยังไม่ได้ยกมาจากตัวเต็ม

ตั้งใจตัดออกให้โครงเบา ค่อยเติมทีละชิ้น:

- กราฟสายเหตุการณ์ (butterfly) — เพิ่มเป็น `src/causal.js` + หน้าใหม่ใน `ui.js`
- ฉากทดสอบแรงกระแทก + เมทริกซ์สหสัมพันธ์ที่วัดจากซีรีส์จริง
- ธีสิสการลงทุน + บันทึกเงื่อนไขที่ทำให้ธีสิสตาย
- หน้าสมุดปูม (`AUDIT` เก็บอยู่แล้วใน `ontology.js` แค่ยังไม่มีหน้าแสดง)

การเพิ่มหน้าใหม่ = เพิ่ม 1 บรรทัดใน `ROUTES` + 1 ฟังก์ชันใน `ui.js`
